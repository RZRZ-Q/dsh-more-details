# 更多详情 · DSH Web Chat

在 DeepSeek Harness 主会话里划选一段文字，点击 **更多详情**，右下角就会打开独立的 DeepSeek 网页讨论并自动发送。聊完后，点 **添加到 DSH**，把讨论作为可重开的引用卡带回主会话，让主模型按需读取正文。

基于 [AHGGG/dsh-side-chat](https://github.com/AHGGG/dsh-side-chat) 扩展，使用真正的 `chat.deepseek.com` 网页聊天和官方 DSH 插件接口。无需修改客户端或授予 macOS 辅助功能权限。

```text
主会话划词 → 更多详情 → 右下角官网 Chat → 历史重开 / 继续追问
                                      ↓ 添加到 DSH
主会话草稿 ← 引用卡 + 正文快照 ← 当前已渲染的网页讨论
     ↓ 用户发送
主模型按需读取正文；引用卡仍能重开原网页聊天
```

## 能做什么

- **独立网页讨论**：侧栏“新建 Chat”打开空白聊天；划词“更多详情”自动带入选文与来源背景。同一来源的活动详情可以接续，切换来源或手动重开历史后，下次划词另建讨论。
- **可修改的默认 prompt**：默认“告诉我更多相关信息”，支持保存和恢复默认；升级保留已保存的自定义内容。选文、所属消息和其他历史分开组织，优先解释选中文本。
- **历史与恢复**：记录插件访问过的聊天地址，重新打开并继续追问。支持记住网页登录、官网语言、小窗宽高和放大状态。
- **可调整的小窗**：拖动左上角、上边或左边调整尺寸；支持放大、还原和收起。调整大小不重建网页、不重复发送。
- **讨论回主会话**：插入草稿引用卡并保留已有文字，由用户发送。正文保存在官方附件存储；主模型通过 `read_webchat_reference` 分页读取，完整退出重开后仍可使用。
- **保留上游选区能力**：“添加到聊天 / 更多详情 / 在侧边对话中提问”跟随 DSH 界面语言。

## 安装和使用

当前版本 **0.3.11**，支持 **DSH 0.2.0-rc.2 与 0.2.1-alpha.4**。两个版本均已在 macOS arm64 的独立官方源码构建环境完成核心流程验收，具体范围见[版本兼容说明](docs/open-source/compatibility.md)。Windows、Linux 尚未验收；网页小窗依赖 Desktop 的浏览器 guest，普通浏览器中的 DSH 不在当前支持范围。

1. 在 DSH **插件 → 添加插件** 安装 `dsh-more-details-0.3.11.tgz`（发布附件或自行构建），启用插件。请停用原 AHGGG 插件，避免两套划词菜单重叠。
2. 完整退出并重开 DSH。点击侧栏 **新建 Chat**，在右下角小窗登录 DeepSeek 官网。该登录与 DSH 模型渠道的账号配置分开。
3. 在主会话一条已完成的消息中划词，点击 **更多详情**，等待网页回复。小窗顶部 **提示词** 或 **设置 → 通用设置 → 更多详情** 可修改默认指令。
4. 用顶部 **新建** 打开空白聊天；用 **历史** 重开已有聊天。重开历史不会再次发送旧问题。
5. 网页回答结束后，确认顶部 **添加到：会话标题**，点击 **添加到 DSH**。主输入框出现引用卡；补充问题后发送，例如“请结合引用中的讨论继续解释，并按需读取正文”。
6. 点击草稿或已发送消息中的引用卡，可回到原网页继续追问。再次添加会更新尚未发送的同一条引用，已经发送的快照保持不变。

若使用 CLI，请使用 **Desktop 自带的 CLI**。以下为 macOS 示例，应用安装位置不同请调整路径：

```sh
"$HOME/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add /absolute/path/dsh-more-details-0.3.11.tgz
```

升级后完整退出重开一次，让 Host 加载新的配置与 RPC 接口；只重新加载插件可能沿用旧接口缓存。不要用另一套独立安装的 CLI 修改 Desktop profile。

## 数据如何流动

点击“更多详情”会将选中文字、所属消息和部分主会话历史作为可见用户消息发送到 DeepSeek 官网。选文上限为 16 KiB UTF-8；来源消息与其他历史分别限 40,000 / 80,000 个 JavaScript 字符单元，历史最近最多五个已完成回合、每回合最多一百条正文消息。超出部分明确标注省略；这些预算不是官网输入上限的承诺。系统/开发者消息、推理块、附件字节不会自动复制，工具调用可作为文字背景。

网页聊天由 DeepSeek 账号保存。插件历史只索引访问过的 URL、标题、来源会话和时间，并不镜像官网全部历史。**添加到 DSH** 另外保存当前已渲染分支的文本快照，始终标记 `partial`；未加载的更早消息、图片和其他非文本内容不在正文中。引用预览是摘要，完整的已采集正文由读取工具分页提供。

`read_webchat_reference` 只读取当前 DSH 会话中用户已经提交的引用，不需要打开官网，不包含登录凭据。添加引用不会创建公开分享链接，也不会自动发送主会话草稿。网页登录记录与正文分开：使用 DSH 凭据服务保存三个必要登录字段及可选语言偏好；默认存储为权限 `0600` 的本地文件，并非 macOS Keychain，不导出完整 Cookie 或浏览器资料。

## 常见问题

- **小窗为什么是英文？** 官网语言独立于 DSH。请在官网设置中选简体中文；插件会记住该偏好，重启后恢复。划词菜单仍跟随 DSH 设置。
- **是否每次都要登录？** 等小窗显示“已记住网页登录”后，可完整退出重开。官网令牌失效或要求重新验证时仍需再次登录。
- **发送状态不明怎么办？** 先查看网页；插件仅在正确聊天中观察到新增用户消息后确认发送，不会自动重复提交不确定的请求。
- **与旧 Codex 完全相同吗？** 本项目复现相近交互并对齐默认指令及来源组织，实际使用 DeepSeek 网页模型；不承诺隐藏上下文或生成答案完全相同。

## 开发与验证

需要 Node.js `^22.19.0 || >=24.0.0`，pnpm 版本见 `package.json`。

```sh
pnpm install --frozen-lockfile
pnpm run check
mkdir -p dist
npm pack --ignore-scripts --pack-destination dist
```

仓库保留 `lib/` 构建产物。`package.json` 的 `private: true` 用于防止误发 npm，不影响源码开源、本地打包或 DSH 安装。当前分发目标为 GitHub 源码和安装包，尚未提交 npm 或 DSH 商店。
